# ADR 0010 — Migration CI Node : 20/22 → 22/24 (retrait Node 20 EOL)

- **Statut** : **accepted**
- **Date** : 2026-07-05
- **Décideurs** : Rudy Rezaire (RezDevOps)
- **Contexte** : chantier transverse « migration CI Node 24 » — dernier repo de la vague (après `rezdevops-site` et `fec-check`)

## Contexte

Node.js 20 a atteint sa fin de vie (EOL) en avril 2026. Côté GitHub Actions, le runtime Node.js 20 utilisé par les actions du marketplace (`actions/setup-node`, etc.) a été retiré le 2026-06-02. Maintenir Node 20 dans la matrice CI revient à tester une plateforme sans couverture de sécurité amont et bientôt indisponible sur les runners.

Le repo `pii-scanner-web` testait jusqu'ici sur `["20", "22"]` (ci.yml) et buildait/déployait sur Node 20 fixe (release.yml `NODE_VERSION`, deploy-pages.yml). Angular 21 (`@angular-devkit/build-angular@21`) déclare `engines.node = ^20.19.0 || ^22.12.0 || >=24.0.0` : Node 22 (LTS active) et Node 24 (prochaine LTS) restent tous deux supportés.

## Décision

**Matrice CI `["22", "24"]`** dans `ci.yml` : retrait de Node 20, conservation de 22 (LTS active), ajout de 24 (validation prochaine LTS). Aligné sur `rezdevops-site`.

**Node de build/déploiement fixé à 22** (LTS active) : `NODE_VERSION: "22"` dans `release.yml`, `node-version: "22"` dans `deploy-pages.yml`.

**Engine `node` bumpé `>=20.19` → `>=22.12`** dans le `package.json` racine et dans les deux packages du workspace (`pii-detectors`, `pii-scanner-engine`, précédemment `>=20.10`), pour une borne unique et cohérente à travers le monorepo. `.nvmrc` : `20` → `22`.

**pnpm inchangé** (`packageManager: pnpm@9.12.0`, `engines.pnpm: >=9`). La montée pnpm 9 → 10 (`--legacy` au déploiement) est un chantier distinct, hors scope de cette migration Node.

**Corepack déjà en place** dans les trois workflows concernés (`corepack enable` provisionne pnpm via le champ `packageManager`) : aucune modification nécessaire. `codeql.yml` n'installe pas Node et n'est pas concerné.

## Justification

- **Sécurité et disponibilité runner.** Node 20 est EOL (avril 2026) et son runtime setup-node a été retiré côté GitHub (2026-06-02). Tester dessus n'apporte plus de garantie et deviendra impossible.
- **Continuité du support Angular 21.** La borne `^22.12.0 || >=24.0.0` couvre exactement la nouvelle matrice ; aucun risque de sortir de la fenêtre supportée.
- **Cohérence inter-repos RezDevOps.** `rezdevops-site` utilise déjà `["22", "24"]` avec build/SSR sur Node 22. Uniformiser `pii-scanner-web` clôt la vague de migration entamée sur les deux autres repos.
- **Borne engine unique.** Ramener les sous-packages de `>=20.10` à `>=22.12` évite un message trompeur (« Node 20.10 suffit ») alors que la CI ne teste plus Node 20.

## Conséquences

- **Aucun changement de code applicatif.** Migration purement infra CI + manifestes. Le `pnpm-lock.yaml` n'a pas à être régénéré (aucun manifeste de dépendance modifié, seuls `engines` changent).
- **Contributeurs sous Node 20.** `pnpm install` warn désormais (et plante avec `engine-strict=true`). Le `.nvmrc` à `22` guide `nvm use` vers la bonne version.
- **pnpm 9 conservé.** Le chantier pnpm 10 reste ouvert et sera traité séparément (ajout de `--legacy` au deploy, cf. mémoire projet).

## Alternatives considérées

- **Garder Node 20 dans la matrice** — rejeté : EOL, runtime retiré des runners, aucune couverture sécurité.
- **Cibler `["20", "22", "24"]`** — rejeté pour la même raison ; tester une plateforme EOL est du bruit CI.
- **Coupler la montée pnpm 10 dans le même sprint** — rejeté pour garder un diff minimal et un scope de validation net (Node uniquement). pnpm 10 introduit son propre piège (`--legacy` au deploy) qui mérite sa propre livraison.
- **Fixer le build sur Node 24** — rejeté : la prod/déploiement doit tourner sur la LTS active (22), 24 reste en validation matricielle jusqu'à devenir LTS.

## Validation

Bumps limités aux workflows (`ci.yml`, `release.yml`, `deploy-pages.yml`), aux manifestes (`package.json` racine + 2 packages), au `.nvmrc` et à la doc (`README.md`, `BOOTSTRAP.md`). Grep résiduel `20` sur les fichiers Node/CI hors historique ADR à zéro. CI attendue verte sur la nouvelle matrice `["22", "24"]`.
